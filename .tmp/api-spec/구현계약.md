### POST /api/health/{metric}/records

**구현 상태**: 구현됨. Bearer 인증 및 UUID `Idempotency-Key` 필수, `201 Created`.

직접 입력 metric은 **sleep, bio, water**만 허용한다. 화면의 다섯 입력 항목은 다음 요청으로 매핑한다.

| 항목 | 경로 metric | 필수 요청 | 선택 요청 |
| --- | --- | --- | --- |
| 수면 | sleep | startAt, endAt, totalSleepMinutes | 없음 |
| 혈압 | bio | bioType=blood_pressure, measuredAt, systolicMmhg, diastolicMmhg | pulseBpm |
| 혈당 | bio | bioType=blood_glucose, measuredAt, bloodGlucoseMgDl | isFasting, insulinMicroIuMl |
| 체성분 | bio | bioType=body_composition, measuredAt, weightKg | heightCm, bodyFatPercent, skeletalMuscleKg |
| 물 | water | consumedAt, amountMl | 없음 |

숫자는 JSON number로 보낸다. 미래 또는 1900년 이전 시각은 허용하지 않는다. 허용되지 않은 필드는 거부한다. 수축기 혈압은 이완기보다 커야 하며 체지방률은 100 이하다. 체성분에 키가 있으면 BMI를 계산한다. 수면 총 분은 정수이며 시작·종료 간격을 넘지 않는다.

응답 `data`: `{recordId, metric, source:"manual"}`. 정확히 같은 측정시각의 원본이 있으면 직접 입력을 우선해 병합하고, 다른 시각은 새 기록이다. 생체는 bioType도 함께 비교한다. 키 재시도는 같은 응답을 반환한다.

**오류**: `400 COMMON-001`, `409 HEALTH-006`, `409 IDEMPOTENCY_KEY_REUSED`.

**근거**: `HealthRecordController`, `HealthRecordInput`, `HealthRecordService.create`.

### PATCH /api/health/water/records/{recordId}

**구현 상태**: 신규 구현됨. Bearer 인증 및 UUID `Idempotency-Key` 필수, `200 OK`.

요청: `{consumedAt, amountMl, recordVersion}`. recordVersion은 조회에서 받은 버전을 그대로 보낸다. **앱에서 직접 입력한 본인 물 기록만** 수정한다. 삼성헬스 원본과 legacy는 수정할 수 없다.

응답 `data`: `{recordId}`. 삼성 원본을 덮은 앱 입력의 시각을 옮기면 원본은 복원하고 새 직접 입력을 만들며 `{recordId, restoredRecordId}`를 반환한다.

**오류**: `403 HEALTH-005`, `404 RESOURCE_NOT_FOUND`, `409 HEALTH-006`(버전·시각 충돌), `409 HEALTH-007`(복원 원본 필요), `400 COMMON-001`.

**근거**: `HealthRecordService.editWater`.

### POST /api/health/water/records/batch-delete

**구현 상태**: 신규 구현됨. Bearer 인증 및 UUID `Idempotency-Key` 필수, `200 OK`.

요청: `{records:[{recordId, recordVersion}]}`. 1~100개, 중복 ID 불가. 본인 앱 입력만 삭제한다. 하나라도 권한·버전 검증이 실패하면 전체를 롤백한다.

응답 `data`: `{deletedRecordIds:[], restoredRecordIds:[]}`. 앱 입력이 삼성 원본을 덮은 기록이면 삼성 원본을 복원하며 원본 자체는 삭제하지 않는다. 나머지 직접 입력은 삭제한다. 수면·혈압·혈당·체성분의 수정·삭제 공개 API는 현재 구현되어 있지 않다.

**오류**: 물 수정 API와 동일한 소유권·출처·버전·원본 검증을 적용한다.

**근거**: `HealthRecordService.deleteWater`.

### GET /api/health/analyses/today

**구현 상태**: 신규 구현됨. Bearer 인증, `category` 쿼리 필수, `200 OK`.

category는 `bio|activity|nutrition|sleep|checkup|overall`이다. 응답 공통 필드는 `{analysisDate, category, cutoff, expiresAt, status}`다. cutoff는 해당 한국 날짜 자정, expiresAt는 다음 자정이다. 생성된 결과가 있으면 report와 generatedAt을 추가한다.

기능 비활성·조회 불가 시 unavailable, 실행 전 pending, 생성 완료 generated, 완료 이력은 있으나 임시 결과가 사라졌으면 result_lost다. 그 밖에는 실행 이력의 상태를 전달한다. **GET은 AI를 생성하거나 재생성하지 않는다.** API 존재와 일일 분석 스케줄 활성화는 별개이며 기능 설정에 따라 unavailable일 수 있다.

**근거**: `HealthAnalysisController`, `HealthAnalysisReader`.

### GET /api/home

**구현 상태**: 구현됨. Bearer 인증, `200 OK`. 온보딩 미완료는 `409 ONBOARDING-001`.

응답 `data`: `{date, alerts, modules}`. 모듈은 `{moduleCode, visible, displayOrder, state, content, emptyStateAction}`이다. 기본 코드는 daily_briefing/key_metrics/medication/missions이며 없으면 기본 모듈을 생성한다.

현재 실제 content를 채우는 모듈은 key_metrics다. `{latestCheckup, latestActivity}`를 반환하며 각각 없으면 null이다. latestCheckup은 `{recordId, measuredAt, providerName, resultCount, findingCount}`, latestActivity는 `{recordDate, steps, activeTimeMinutes}`다. 나머지 모듈은 content=null과 빈 상태 안내를 제공하며 alerts는 빈 배열이다. 이 응답을 미션·복약·브리핑 API 구현 완료로 간주하지 않는다.

**근거**: `HomeController`, `HomeService`, `HomeSummaryRepository`.

### GET /api/chat/sessions

**구현 상태**: `heapy.chat.enabled=true`일 때 제공. Bearer 인증, `200 OK`.

쿼리: limit 기본 20, 1~50; cursor 선택. `data`는 `{items:[Session], nextCursor}`다. Session은 `{sessionId, title, companionCode, createdAt, lastMessageAt}`. meta가 아니라 data 내부에 페이지 정보가 있다.

**근거**: `ChatController`, `ChatModels`, `ChatService`.

### POST /api/chat/sessions

**구현 상태**: 상담 기능 활성 시 제공. Bearer 인증 및 UUID `Idempotency-Key` 필수, `201 Created`.

요청 `{companionCode:"heapy_cat"}`. companionCode는 `heapy_cat|heapy_dog`만 허용한다. 응답 data는 Session이다. 같은 키·본문은 같은 세션을 반환하고 다른 본문은 409다.

**근거**: `ChatModels.CreateRequest`, `ChatService.create`.

### GET /api/chat/sessions/{sessionId}

**구현 상태**: 상담 기능 활성 시 제공. Bearer 인증, `200 OK`. 응답 data는 Session이다. 본인 세션이 아니거나 없으면 `404 RESOURCE_NOT_FOUND`.

**근거**: `ChatService.session`.

### PATCH /api/chat/sessions/{sessionId}

**구현 상태**: 상담 기능 활성 시 제공. Bearer 인증, `200 OK`.

요청 `{title?, companionCode?}`. title은 1~100자, companionCode는 heapy_cat/heapy_dog이며 최소 한 필드를 전달한다. Idempotency-Key는 요구하지 않는다. 응답 data는 Session이다. 과거 메시지의 companionCodeSnapshot은 바꾸지 않는다.

**근거**: `ChatModels.UpdateRequest`, `ChatService.update`.

### DELETE /api/chat/sessions/{sessionId}

**구현 상태**: 상담 기능 활성 시 제공. Bearer 인증, 성공 `204 No Content`.

본인 세션을 삭제한다. Idempotency-Key는 요구하지 않는다. 관련 메시지·출처·요약은 세션 삭제 정책에 따라 함께 정리한다. 진행 중 요청 등 충돌 상태는 `409 CHAT-002`로 거부한다.

**근거**: `ChatService.delete`.

### GET /api/chat/sessions/{sessionId}/messages

**구현 상태**: 상담 기능 활성 시 제공. Bearer 인증, `200 OK`.

쿼리 limit 기본 20, 1~50; cursor 선택. data는 `{items:[Message], nextCursor}`다.

Message 필드는 messageId, role, content, messageOrder, responseStatus, createdAt, citations, suggestedActions, companionCodeSnapshot이다. citation은 `{displayOrder, sourceTitle, sourceUrl, documentId}`다. 현재 suggestedActions는 빈 배열이며 이를 AI 제안 승인 기능 구현으로 간주하지 않는다.

**근거**: `ChatModels.Message`, `ChatService.messages`.

### POST /api/chat/sessions/{sessionId}/stream

**구현 상태**: 상담 기능 활성 시 제공. Bearer 인증 및 UUID `Idempotency-Key` 필수.

요청 Content-Type은 application/json, 본문은 `{message:"사용자 질문"}`이며 공백만 불가·최대 2000자다. 성공 응답은 `200 text/event-stream`으로 공통 JSON 봉투를 쓰지 않는다.

~~~text
event: status
data: {"stage":"retrieving","message":"관련 건강 정보를 확인하고 있어요."}

event: delta
data: {"content":"완성된 답변 본문"}

event: done
data: {"sessionId":"11111111-1111-4111-8111-111111111111","userMessageId":"22222222-2222-4222-8222-222222222222","assistantMessageId":"33333333-3333-4333-8333-333333333333","responseStatus":"completed","citations":[],"metadata":{}}
~~~

현재 공개 delta는 생성·저장 후 답변 전체를 한 번에 전송한다. 토큰 단위 실시간 스트리밍으로 가정하지 않는다. 실패 시 error 이벤트는 `{code:"CHAT-001", message, traceId}`다. 연결 수락 전의 검증·충돌 오류는 일반 JSON 오류 응답이다.

응답 상태는 completed/partial을 구분한다. 현재 인스턴스의 동시 스트림 상한은 2, SSE 제한 시간은 105초다. 동일 키 완료 요청은 저장한 결과를 재사용한다. 내부 진단은 별도로 보관하며 사용자 데이터나 내부 예외 원문을 공개 오류에 넣지 않는다.

**근거**: `ChatController.stream`, `ChatService`, `ChatGateway`.
