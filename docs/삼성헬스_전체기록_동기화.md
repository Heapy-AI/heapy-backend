# 삼성헬스 전체 기록 동기화

작성자: 김진우

## 반영 범위

사용자가 2026-09-10 요청한 실제 삼성헬스 읽기 → 인증된 Spring API → 기존 생활 건강 테이블 저장을 구현한다. 권한 확인이나 오늘 걸음 조회만으로 전체 동기화 성공을 표시하지 않는다.

초기 범위는 한국 날짜 기준 오늘 포함 최근 365일이다. 수면·심박수·혈당·혈압·체성분·운동·물·영양은 원본 ID로 저장한다. 이후 수정·삭제 로그를 읽는다. 걸음·오른 층수·활동 요약은 삼성 SDK 일별 집계를 활동 테이블에 합친다. 변경 로그가 없는 집계는 최근 365일을 30일씩 나눠 다시 읽는다.

마이탭 연결과 내 건강 아래로 당기기는 같은 동기화를 실행한다. 내 건강 진입·앱 복귀·15분 간격에 실행하되 최근 성공 후 15분은 자동 실행을 생략한다. 앱이 백그라운드로 이동하면 다음 페이지 읽기를 중단한다. 백그라운드 1시간 실행은 아직 활성화하지 않는다.

## API 계약

- `GET /api/health-sync-state?connectionId=UUID`: 본인 설치의 `cursorState`와 서버 시각.
- `POST /api/health-sync-runs`: 본인 JWT, UUID `Idempotency-Key` 필수. 최대 500건·1MiB.
- `GET /api/health-sync-runs/{syncRunId}`: 본인 배치의 저장 결과.

요청은 `connectionId`, `syncMode`, `dataType`, `records`, 선택적 `through`를 받는다. `syncMode`는 기존 DB 제약에 맞춰 `app_open`, `manual_refresh`, `foreground`, `background`를 사용한다. 클라이언트는 현재 수동·전경만 사용한다. `dataType`은 수면·생체 4개·운동·활동·물·영양의 9개 스트림이다.

각 기록은 `metric`, `externalRecordId`, `sourceUpdatedAt`, `operation: UPSERT|DELETE`, `data`를 포함한다. `externalRecordId`는 `dataType:SDK원본ID`, 활동은 `activity:YYYY-MM-DD`다. `data`의 날짜·수치는 기존 DB 필드를 camelCase로 변환한 명칭이다. 삭제에는 측정값이 필요 없다. 사용자 ID와 출처는 요청에서 받지 않는다.

원자적 저장이 끝난 뒤 HTTP 200, `status=succeeded`, 수신·삽입·변경·생략·삭제 건수를 반환한다. 실패한 배치는 롤백된다. 동일 키·본문 재시도는 이전 응답을 반환하고, 같은 키의 다른 본문은 409다. SDK 마지막 페이지 저장에만 `through`를 보낸다. 모든 스트림 완료 시각의 최솟값이 설치의 `last_synced_at`이다. AI 분석은 호출하지 않는다.

## 원본과 직접 입력

원본 ID별 버전과 삭제 이력을 비공개 테이블에 보존한다. 오래된 자료의 재수신은 무시하며 삭제된 자료가 과거 배치 재시도로 부활하지 않는다. 같은 버전이면 삭제를 우선한다. 사용자 행 잠금을 직접 입력 서비스와 공유한다.

앱 직접 입력은 덮어쓰지 않는다. 물 직접 입력이 삼성 원본을 가리는 경우 최신 삼성 원본을 별도 보존한다. 직접 입력을 삭제하면 최신 원본과 출처·버전을 복원한다. 삼성에서 원본을 삭제하면 직접 입력은 남기고 원본 연결만 해제한다.

수치가 없는 활동 항목은 NULL로 저장한다. SDK 집계가 없는 날짜는 해당 날짜의 삼성 원본만 제거한다. 앱 직접 입력은 제거하지 않는다.

## 단위 매핑

| 항목 | SDK → DB |
| --- | --- |
| 혈당 | mmol/L × 18.0182 → mg/dL |
| 혈압 | mmHg 유지 |
| 체중·신장 | kg·cm 유지 |
| 골격근량 | SKELETAL_MUSCLE_MASS kg 사용. 비율 필드 사용 안 함 |
| 수면·활동시간 | Duration → 분, 소수 분 버림 |
| 운동시간 | Duration → 초 |
| 거리·물 | m·mL 유지 |
| 영양 | SDK 영양소 단위 유지 |
| 주입 인슐린 | 혈중 인슐린 농도와 단위·의미가 달라 저장하지 않음 |

심박수·혈당은 HealthDataPoint 대표 측정값을 저장하며 내부 SERIES_DATA를 별도 중복 저장하지 않는다. 운동은 원본 세션의 시간·열량을 합산한다. 층수는 현재 정수 DB에 맞춰 소수부를 버린다. 처음 읽는 과거 원본의 내부 센서 시계열이나 운동 경로는 이 화면의 저장 범위에 포함하지 않는다.
