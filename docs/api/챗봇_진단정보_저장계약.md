# 챗봇 진단정보 저장 계약

## 목적과 적용 범위

사용자가 요청한 개발 서버의 챗봇 응답 실패 추적을 위한 추가 계약이다. 공개 앱 API와 내부 계약 버전 1.0을 유지하며 내부 응답에 선택 필드 `diagnostics`를 추가한다. 기존 앱 변경은 필요 없다. 검진 버전 2 계약은 변경하지 않는다.

## 수집 정보

기존 개발자 데모 결과에서 질문 의도, 분류 신뢰도, 모델 버전, 검증 방식·상태, 근거 여부, 검색·인용·실패 컬렉션 개수, 개인 문맥 사용 여부, 불확실·안전 가드·긴급 분기 여부만 선별한다. 본문, 질문 재작성 결과, 대화 요약, 검진 수치, 검색 문서 원문, 자유 서술 검증 사유는 복제하지 않는다.

내부 성공 응답의 `diagnostics`는 서버 허용 목록에 있는 불리언·유한 수·상태 토큰만 저장한다. 알 수 없는 필드는 무시한다. 내부 오류 이벤트에는 `stage`, `diagnosticCode`만 추가한다. 공개 오류 메시지는 유지한다.

## 저장·접근·보존

`private.chat_diagnostics`에 요청 ID, 재시도별 고유 시도 ID, 세션 FK, 상태, 마지막 단계, 오류 코드, 소요 밀리초, 내부 HTTP 상태, 제한된 JSONB를 저장한다. 시작과 완료·실패 상태를 같은 시도 행에 기록한다. 시작만 남으면 처리 중단 가능성을 확인할 수 있으나 원인을 단정하지 않는다.

JSONB 최대 4096바이트. 앱·익명·일반 인증·서비스 역할에 테이블 권한을 주지 않고 RLS를 활성화한다. 현재 확인된 백엔드 DB 역할 postgres가 기록한다. 세션 삭제 시 함께 삭제되며 진단 기록만 14일 보관 후 시간당 최대 1000건씩 정리한다. 대화 메시지에는 정리 정책을 적용하지 않는다.

답변 저장 트랜잭션과 독립된 최대 3초 트랜잭션으로 기록한다. 진단 DB 쓰기가 실패하면 요청 추적 ID와 고정 오류 코드만 서버 로그에 남기며 상담을 실패시키지 않는다. SQL 실패는 원문 대신 SQLSTATE만 보존한다. 예외명·메시지·스택·키는 보관하지 않는다.

## 적용 및 복구

대상은 공유 Supabase `panaspvsdszeapkoltna`이며 개발 전용 DB로 간주하지 않는다. 개발 EC2에서 백엔드와 FastAPI를 배포한다. 사용자의 이번 구현·전체 적용 요청에 따라 신규 진단 테이블 한 건만 적용한다.

`20260909075748_chat_diagnostics.sql`과 이력 등록을 하나의 명시적 트랜잭션으로 실행한다. 잠금 5초, 문장 60초, 유휴 60초 제한이며 기존 테이블·결과·마스터 값은 수정하지 않는다. 세션 FK 생성 시 짧은 잠금이 발생할 수 있다. 사전 조건 불일치 시 중단한다.

실패 시 트랜잭션 롤백. 적용 후 문제가 발생하면 이전 백엔드·FastAPI 이미지로 되돌리고 추가 테이블은 유지한다. 공유 DB 전체 복원은 사용하지 않는다. 신규 진단 데이터 삭제가 필요한 되돌림은 별도 검토한다. 미검토 마이그레이션은 함께 적용하지 않는다.
